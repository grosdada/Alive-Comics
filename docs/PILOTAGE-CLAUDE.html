Piloter Alive-Comics (pour une instance de Claude)

Ce guide te permet de construire seul une planche de BD animée complète avec l'application Alive-Comics, uniquement par HTTP : découpage, images, mouvements de caméra, actions, sons, voix off, rendus sur les machines de David, vérification, export et publication. Tu es le cerveau : n'utilise pas l'IA intégrée de l'application. David te donnera un thème et des chemins de fichiers (images, sons).

1Ton rôle et les règles

  • Tu décides de tout : découpage, ordre de lecture, mouvements, actions, textes (en anglais pour H3), sons, voix off (en français). N'appelle jamais /api/projects/<id>/direct (le réalisateur IA intégré) ni /api/llm/* : c'est toi l'intelligence.
  • Tu ne modifies jamais les fichiers du projet à la main (projects/<id>/project.json etc.) pendant que le serveur tourne : passe toujours par l'API (elle gère les verrous, les versions et la fusion avec l'interface).
  • David peut avoir l'interface ouverte sur la même planche : elle se recharge seule quand tu modifies la planche (numéro de version rev). Évite seulement de modifier une planche pendant qu'il la modifie lui-même.
  • Ce qui coûte de l'argent (fal.ai) : la voix off (voice.mode = tts), les bruitages cloud (foley.engine = hunyuan | mmaudio) et les rendus avec target: "fal" ou "auto". Tout le reste tourne gratuitement sur les machines de David (ComfyUI). Par défaut, reste en local ; n'utilise fal que si David le demande.
  • Publier met la page en ligne (lien public, non indexé) : ne publie que si David te l'a demandé.
  • Réponds et rends compte à David en français.

Client minimal (bibliothèque standard)

import json, urllib.request
BASE = "http://127.0.0.1:8790/api"

def api(method, path, body=None, raw=None, timeout=600):
    data = raw if raw is not None else (json.dumps(body).encode() if body is not None else None)
    ctype = "application/octet-stream" if raw is not None else "application/json"
    req = urllib.request.Request(BASE + path, data=data, method=method, headers={"Content-Type": ctype})
    try:
        with urllib.request.urlopen(req, timeout=timeout) as r:
            return json.loads(r.read() or b"null")
    except urllib.error.HTTPError as e:
        raise RuntimeError(f"{method} {path} -> {e.code} {e.read().decode()[:500]}")

4Catalogue : caméras et actions

Deux familles de cases :

  • Temps figé, caméra pilotée au glisser : caméra orbit360, arc, demi_arc, vertical, travelling avec l'action fige. La scène est immobile, le lecteur fait bouger la caméra en glissant. Parfait pour les compositions fortes, les objets, les tableaux.
  • Plan animé, lecture automatique : n'importe quelle caméra avec une action autre que fige (ou les caméras fixe, grue, avancee, epaule, custom). La case joue seule, en boucle si action.loop est vrai (valeur par défaut : la dernière image rejoint la première).
  • fixe + fige sans précisions = image fixe (pas de vidéo). Des camera.extra suffisent à en faire une vidéo.
  • Dans le lecteur, les plans animés ne bougent qu'au survol (démarrage et arrêt en douceur) ; au doigt, la dernière case touchée joue.
  • Tremblé caméra ajouté au montage (camera.shake : aucun, leger, moyen, fort ; moyen par défaut pour epaule) : dérive lente et discrète ajoutée à l'export, sans nouveau rendu, boucle intacte.

5Écrire pour MiniMax H3 (leçons mesurées)

  1. Anglais pour tous les champs, précisions et ambiances. Français seulement pour la voix off.
  2. Les champs sont insérés dans des phrases : subject est un groupe nominal court (« the golden mask ») ; left, right, ending, close, wide, toward sont des groupes nominaux décrivant la vue d'arrivée (« a three-quarter view of his face, the round glasses in front »), jamais une phrase, jamais le mot « camera ».
  3. Décris où la caméra arrive, pas seulement « gauche / droite » (H3 ignore gauche/droite, il suit une destination décrite).
  4. Nomme le sujet précisément ; pour un arc, décris deux arrivées vraiment opposées.
  5. Mouvement fort, constant, visible pour les actions (« never stop moving », « clearly visible for the whole shot ») et dis ce qui reste immobile.
  6. Textures sans « côté » (tentacules, amas) : caméra vertical. Vers un détail : travelling (un vrai travelling, pas un zoom).
  7. Varie les plans sur la page ; adapte le mouvement à la forme de la case (large : arc, travelling ; haute : vertical, grue).
  8. Une case = une vidéo de 3 s par demi-arc (73 images) ou 5,2 s (124 images) : ne décris pas une histoire longue dans une case.
  9. Durées et tailles sont automatiques (≈ 0,8 Mpx au format de la case, côté long ≤ 1344). Limite H3 : 15 s par rendu.
  10. « style » (ambiance commune, anglais) s'ajoute aux plans animés : époque, lumière, grain (« Warm 1970s film look »).

6Les sons

Jusqu'à trois couches par case + un son global de page. Tous les sons sont égalisés à l'export (ambiance -24, bruitages -21, voix -17, page -23 LUFS) ; les volumes (0 à 1) règlent ensuite le mélange.

8La recette, du thème à la page

  1. Lire le thème et regarder les images fournies (tu peux les ouvrir : formats, sujets, cadrages). Imaginer l'histoire en N cases, l'ordre de lecture, la case forte (la plus grande), le ton sonore.
  2. Vérifier les machines : GET /api/workers (au moins une avec pf.video).
  3. Créer la planche : POST /api/projects avec format, sens et un découpage dont le nombre de cases correspond aux images. Lire geometry.panels : trier par order, noter la forme de chaque case (rect).
  4. Placer les images : chaque image dans la case dont la forme lui convient (paysage dans une case large…), par /panels/<case>/image. Ajuster view si le sujet est coupé (zoom 1–1,4, ox/oy ±0,2).
  5. Régler chaque case (/panels/<case>) : caméra + action + champs (anglais), loop, rigid, extra ; sons.
  6. Régler la page (/update) : style, pageSound, couleurs si besoin.
  7. Composer (/compose) et regarder projects/<id>/page/page.jpg et les start/<case>.png (ce que H3 verra).
  8. Relire les prompts avec /api/plan pour chaque case.
  9. Lancer les rendus (/render, target: "local") : 3 à 11 min par vidéo, réparties sur les machines (une machine occupée garde la tâche dans sa file). Un arc = 2 vidéos (L et R).
  10. Suivre GET /api/jobs?project=<id> toutes les 30–60 s jusqu'à ce que tout soit done ou error.
  11. Vérifier chaque vidéo (section 9), relancer ce qui est raté avec une autre graine ou un autre réglage.
  12. Exporter (/export) et donner à David le chemin projects/<id>/export/index.html (ou l'URL locale http://127.0.0.1:8790/projects/<id>/export/index.html). Publier seulement s'il le demande.

8 bisPlusieurs pages à la suite

  • Pas besoin d'attendre qu'une page soit finie pour lancer la suivante : la file de rendus est commune à toutes les planches. Prépare une page (création, images, réglages, /compose, contrôle des prompts), lance son /render, passe à la suivante. Les tâches s'empilent et se répartissent sur toutes les machines libres, dans l'ordre d'envoi.
  • Chaque machine enchaîne d'abord les vidéos, puis les sons (MiniMax Music 3) quand il n'y a plus de vidéo pour elle : ça évite de recharger les modèles. Les ambiances arrivent donc plutôt en fin de file.
  • Suivi global : GET /api/jobs (sans project) ; par page : GET /api/jobs?project=<id>. Quand toutes les tâches d'une page sont done, vérifie-la et exporte-la, même si les suivantes calculent encore.
  • N'exporte une page qu'après ses rendus : avant, ses cases resteraient des images fixes (l'export le signale dans report : « rendu manquant »).
  • Ordre de grandeur, 3 machines : une vidéo prend 4 à 11 min, un arc en compte deux. Une page de 6 cases ≈ 8 à 10 vidéos ≈ 20 à 30 min ; 10 pages ≈ 3 à 5 h de calcul, plus les sons. Pour aller plus vite, préfère les caméras à une seule vidéo (plans animés, demi_arc, orbit360) aux arc, vertical et travelling (deux vidéos).
  • La file survit à un redémarrage du serveur (les rendus en cours sont repris). Une erreur passagère de mémoire vidéo est relancée une fois automatiquement, sur une autre machine si possible ; regarde quand même errors à la fin.
  • Pour faire de la place dans la liste des tâches : POST /api/jobs/clear {"project": "<id>"} (efface les terminées).

9Vérifier et corriger les rendus

  • Après chaque rendu, GET /api/projects/<id> : panels[case].renders liste toutes les variantes, chosen la vidéo utilisée (la plus récente par défaut).
  • Indice de mouvement : chaque variante a un champ motion (écart moyen entre images successives). Repères mesurés : moins de 0,3 = presque immobile (à refaire si la case devait vivre : action plus forte, précisions plus explicites, autre graine) ; 1,5 à 4,5 = une case qui bouge bien. Les cases « temps figé » pilotées au glisser bougent par la caméra : leur indice est normalement entre 1 et 4.
  • Regarde les images : extrais la première, celle du milieu et la dernière image avec ffmpeg et ouvre-les : 
    ffmpeg -v error -y -i projects/<id>/renders/p3/V_s904231_xxxx.mp4 \
  -vf "select='eq(n\,0)+eq(n\,60)+eq(n\,123)',scale=-1:240,tile=3x1" -frames:v 1 controle_p3.jpg
    Pour un arc, contrôle L et R : leurs dernières images doivent montrer des côtés opposés. Le flux optique ne juge pas bien le sens : fie-toi à ce que tu vois.
  • Défauts connus et remèdes :
    • les deux côtés d'un arc partent du même côté : décrire des arrivées plus différentes, ou passer en demi_arc ;
    • l'objet pivote sur lui-même : camera.rigid = true ;
    • quasiment rien ne bouge : angle plus grand (amplitude: grand), action plus forte, ou autre graine ;
    • une vingtaine d'images presque noires (« volet noir ») : autre graine ;
    • plan animé presque figé (motion < 0,3) : les mots « slow », « tiny », « stays in place » freinent H3 ; écrire un mouvement continu et visible (le preset vie le fait depuis le 14/10/2026), ou passer en nerveux ;
    • zoom au lieu d'un déplacement : travelling écrit « a dolly in and not a zoom » (déjà dans le gabarit).
  • Relancer : POST /panels/<case> {"seed": <graine+1>} puis /render sur cette case ; ou "seeds": {"p3": 12345} dans /render. Choisir ensuite la meilleure variante avec /choose.

9 bisRetouches sans régénérer (mode édition)

David retouche les cases dans l'aperçu (bouton « ✏️ Éditer » de la page exportée, servie par l'application). Tout ce qui suit est appliqué par le lecteur, en direct : aucun ré-encodage, réversible. Tu peux le régler aussi par POST /api/projects/<id>/edit/<case> avec {"edit": {...}} (l'objet remplace l'ancien : relis panels[case].edit d'abord et renvoie-le complété).

  • Repères du tremblé : léger {size 0.4, freq 0.2, rot 0.046}, moyen {0.8, 0.2, 0.092}, fort {1.3, 0.2, 0.143}, nerveux {0.9, 1.1, 0.2}. Le tremblé suit l'image (il se fige quand la case se fige).
  • Raccord garanti : le tremblé est calculé sur la position dans la boucle, avec un nombre entier de cycles entre le début et la fin (freq est arrondie à la boucle). Il est donc identique au in et au out, quels que soient les réglages et les points de boucle. Le bouton « Adaptive loop » de l'éditeur cale freq sur la valeur jouée.
  • Préréglages de tremblé de David (toutes planches) : GET /api/userpresets -> {"shake": [{"name", "size", "freq", "rot"}]} ; POST /api/userpresets {"kind": "shake", "name", "value"} (ou "delete": true). Un préréglage ne garde pas la graine : chaque case garde la sienne.
  • Suivi des cases : en mode édition, une pastille en haut à droite de chaque case dit où en est David : orange = à voir (défaut), vert = OK, rouge = à retoucher. C'est panels[case].review (null, "ok" ou "redo"), réglable par POST /edit/<case> {"review": "redo"}. Si David te demande de reprendre un livre, commence par les cases "redo" et ne touche pas aux "ok".
  • Depuis le 15/10/2026, le tremblé n'est plus incrusté dans la vidéo à l'export : les vidéos sont ré-encodées une fois sans lui, puis le lecteur l'applique.
  • Le « fixe » qui casse une boucle est un ralenti : H3 freine sur les 10 à 20 dernières images (et les premières) pour retomber sur l'image de départ. "ease": {"head": 8, "tail": 16, "gain": 2} les joue plus vite, sans couper : la boucle reste parfaite. (Couper avec range + xfade reste possible, mais le raccord se voit davantage.)
  • Sons : volumes règle les couches existantes, /sound?layer=extra ajoute un son par-dessus, pageVolume règle la musique de la page.
  • Pas de son en double : tout import de son (/upload?kind=audio|voice|page, /panels/<case>/sound) est reconnu par son contenu. S'il sert déjà dans une planche, la réponse est 409 avec {"duplicate": true, "used": [{"where": …}]} : ne force (&force=1) que si la réutilisation est voulue (ex. même musique sur tout un livre). S'il a déjà été importé sans servir, le fichier existant est repris ("reused": true).

9 terRelief : une photo en relief au lieu d'une vidéo

Chaque case a un traitement : "treatment": "h3" (défaut, vidéo MiniMax H3, ~7 min de GPU) ou "treatment": "relief" (photo en relief : une carte de profondeur calculée en ~1 s sur le processeur de ce PC par Depth Anything V2 Small, licence Apache 2.0 ; aucune vidéo). Le lecteur bouge la caméra de quelques pour cent au survol ou au clic, et suit le glisser. Une case H3 dont le rendu n'est pas encore là s'affiche en relief en attendant.

Relief en couches (sans bords dédoublés) : « Calculer » découpe chaque case en relief en un fond reconstruit (sans les personnages) et 1 ou 2 calques de personnages détourés, chacun avec sa profondeur, comme un livre pop-up. SAM 3.1 + BiRefNet (détourage), Depth Pro (profondeur), Qwen-Image-Edit 2509 (décor caché) ; ~1 min par case à chaud ; tâche « Couches relief » dans la file. meta.n = nombre de calques ; n = 0 avec reason : la case ne se découpe pas (paysage, foule…), elle garde la nappe simple. Foules (sujets sur plus de 45 % de la case) : seul le premier plan net est détaché, le reste de la foule reste dans le décor ; meta.crowd = true. Pas de premier plan net : pas de couches, la case glisse d'un bloc (carte plane, sans déformation). Version 3 : cartes plates à contour net, objets tenus (SAM), décor PLATE = qwen | lama | hybride (voir ALIVE-COMICS-DOC). À contrôler dans l'aperçu (mode édition, onglet Relief, vue « Calques »).

  • Réglages : panels[case].relief = {"preset": "respire|glisse|tourne|vertigo", "amount": 0.025, "focus": 0..1, "duration": 2, "trigger": "hover|click"}. focus = plan net (profondeur qui ne bouge pas : la mettre sur les visages) ; sans elle, médiane du centre de la case.
  • Presets : respire (portraits, couples, détails), glisse (groupes, paysages), tourne (sujet central détaché), vertigo (moments forts). Cheveux, voiles, vitres : rester sous 3 % d'amplitude.
  • Formule conseillée : relief partout, et un « biscuit » H3 (orbite 360 ou plan vivant en boucle) par page, dans la grande case qui le mérite. Le réalisateur IA sait le faire (option « Relief partout + biscuits H3 »).
  • Couleurs (edit.grade) et cadrage (edit.frame) s'appliquent aussi au relief ; pas de tremblé.

Le réalisateur IA lit à chaque demande la compétence app/skills/boucles.md (écrire des boucles parfaites, tirée de docs/BOUCLES-IA.html) et ne touche jamais aux cases vertes.

10Exporter, publier, livres

  • /export assemble la page jouable (vidéos tout-intra, sons égalisés, lecteur). Les cases sans vidéo restent des images.
  • /publish l'envoie sur https://alive-comics.placenta.tv/<nom>/ (SSH, clé de ce poste déjà réglée) et met à jour la page d'accueil. Nom : minuscules, chiffres, tirets.
  • Un livre enchaîne plusieurs planches : PUT /api/books (lire d'abord GET /api/books et ajouter ton livre à la liste, sans effacer ceux de David), puis /api/books/<id>/publish. Un livre d'une seule page n'a pas de flèches.

11Pièges connus

  • Les rendus sont longs : ne lance pas plus de cases que nécessaire, regroupe-les en un seul /render.
  • Une case fixe + fige sans précisions ne produit aucune vidéo (/render le signale dans errors).
  • Après un changement d'image ou de découpage, recompose (/compose) avant de rendre.
  • fal refuse parfois une description (filtre de contenu) : l'erreur l'explique, reformule plus factuellement.
  • Si une tâche est en error avec « injoignable » : la machine est éteinte ; relance sans la préciser dans machines.
  • Ne redémarre pas le serveur pendant des rendus sans nécessité (ils sont repris, mais l'interface de David perd la connexion un instant).

import json, time, urllib.request
BASE = "http://127.0.0.1:8790/api"
def api(method, path, body=None, raw=None, timeout=600):
    data = raw if raw is not None else (json.dumps(body).encode() if body is not None else None)
    req = urllib.request.Request(BASE + path, data=data, method=method,
        headers={"Content-Type": "application/octet-stream" if raw is not None else "application/json"})
    with urllib.request.urlopen(req, timeout=timeout) as r:
        return json.loads(r.read() or b"null")
