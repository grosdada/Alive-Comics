1 · Le concept

Entre la bande dessinée et le cinéma

Une planche vivante garde tout ce qui fait une page de BD : des cases, des gouttières, un ordre de lecture, des images qu'on regarde à son rythme. Mais chaque case contient quelques secondes de temps, qui se réveillent sous la main du lecteur.

  • Une planche reste une planche : au repos, la page est calme et se lit comme sur papier.
  • Deux façons de faire vivre une case : une vidéo MiniMax H3 en boucle (~5 s, la dernière image rejoint la première), ou une photo en relief (une carte de profondeur, la caméra bouge de quelques pour cent).
  • Le lecteur réveille les cases : rien ne bouge avant le survol ; certaines cases figent l'instant et laissent tourner la caméra au glisser.
  • Le son vient avec le regard : voix off, ambiance, bruitages par case, musique de page dessous.
  • L'auteur réalise, la machine exécute : images et voix de l'auteur, mouvement calculé sur ses PC ; retouches sans recalcul ; un thème entier peut être confié à une autre instance de Claude.
  • Un lien suffit : une page web autonome, publiée sur alive-comics.placenta.tv, page seule ou livre.

2 · Reprendre ailleurs

Passer sur un autre PC

Le code est sur GitHub ; les planches, les réglages et les clés ne le sont pas. Dans l'ordre :

  1. Installer les outils

    Python 3.11 ou plus, Git, et ffmpeg dans le PATH (export, analyse des vidéos).

  2. Récupérer le code
    git clone https://github.com/grosdada/Alive-Comics.git
cd Alive-Comics
pip install -r requirements.txt        # pillow, numpy, onnxruntime
  3. Copier ce qui n'est pas dans Git

    Depuis E:\Codex projects\Alive-Comics sur ce PC (par le réseau ou un disque) :

    QuoiTailleContenuIndispensable
    projects/5,7 Gotoutes les planches : project.json, images, rendus, cartes, exportsoui
    local_settings.jsonquelques Koclés Anthropic et fal, machines ComfyUI, réglages de publicationoui
    data/books.json, data/folders.json (projets de rangement des planches), published.json, user_presets.jsonpetitslivres, projets de rangement, registre des publications, préréglages de trembléoui
    data/jobs.json, sound_index.jsonpetitsfile de rendus (historique), empreintes des sonsutile
    data/books/2,3 Golivres assemblésnon : « Aperçu » les refait
    data/models/95 MoDepth Anything V2 Smallnon : retéléchargé au premier relief
     
    robocopy "\\PC-SOURCE\E$\Codex projects\Alive-Comics\projects" projects /E /MT:16
robocopy "\\PC-SOURCE\E$\Codex projects\Alive-Comics\data" data /E /XD books models
copy "\\PC-SOURCE\E$\Codex projects\Alive-Comics\local_settings.json" .

    Adapter le chemin source. Ne jamais mettre local_settings.json, projects/ ni data/ dans Git.

  4. Vérifier le réseau

    Le nouveau PC doit joindre les trois machines ComfyUI (HITCHCOCK, CASSAVETES, FORD) : leurs adresses sont dans Réglages › Machines. Dans l'en-tête de l'appli, une pastille verte par machine.

  5. Publier depuis ce PC

    Chaque PC a sa propre clé SSH. Réglages › Publication affiche la clé publique du poste : David l'ajoute dans hPanel (Hostinger, accès SSH), puis « Tester la connexion ».

  6. Lancer

    Lancer_Alive_Comics.bat (ou python -m app) puis http://127.0.0.1:8790. Un second lancement ouvre juste le navigateur (port exclusif).

  7. Claude Code

    Ouvrir le dossier du dépôt : CLAUDE.md et la compétence .claude/skills/boucle-parfaite (avec loopcheck.py et loopfix.py) sont chargés d'office. L'instance qui fabrique les livres se branche sur l'API du PC qui fait tourner le serveur.

  8. Contrôler

    Réglages : tester l'IA, fal, la publication ; ouvrir une planche, « Aperçu », puis « ✏️ Éditer ». Pour le relief : passer une case en relief, la carte arrive en environ une seconde (le premier usage télécharge le modèle).

3 · Architecture

Comment c'est construit

Un serveur Python local (bibliothèque standard, plus Pillow, NumPy et onnxruntime), une interface web sans compilation, un lecteur autonome copié dans chaque export. Les calculs vidéo partent sur des machines ComfyUI du réseau, ou sur fal.

5 · Dans l'application

Fabriquer une planche

Page et découpage

  • Formats : page BD, manga, 4:5, carré, écran ; vertical ou horizontal.
  • Découpages prêts ou au hasard ; glisser un trait déplace la frontière, glisser un bout l'incline (Maj : droit).
  • Couper, supprimer, pivoter ; fond, traits, gouttière, marge, ambiance commune ; Ctrl+Z / Ctrl+Y.
  • Images : glisser sur la case, molette pour zoomer, glisser pour recadrer.

Chaque case

  • Traitement : « Vidéo H3 » ou « Relief (instantané) ».
  • Caméra (vidéo) : temps figé piloté au glisser (orbite 360°, arc, demi-arc, plongée ↕ contre-plongée, travelling) ou scène animée (fixe, grue, avancée, épaule, texte libre).
  • Action : figé, vie en boucle, nerveux, danse, marche, parole, éléments, texte libre ; « Animation en boucle » cochée par défaut.
  • Sons : voix off (ton MP3), ambiance, bruitages ; « ✨ Écrire les textes avec l'IA ».
  • Rendus : graine, variantes avec indice de mouvement, prompt envoyé à H3, prompt réécrit depuis l'aperçu.

6 · Option relief

Une photo en relief au lieu d'une vidéo

Une case en relief n'a pas de vidéo. Version 2 : un diorama en couches, comme un livre pop-up : le fond sans les personnages (reconstruit par l'IA), puis chaque personnage détouré, chacun avec sa propre profondeur. Plus de bords dédoublés, et ce qui était caché derrière les sujets apparaît quand la caméra bouge. Au repos, la case est exactement la photo. En attendant les couches (ou si la case ne se découpe pas), une nappe de profondeur sans pli sert de relief. Détails : docs/PARALLAXE-RELIEF.html, app/layers.py.

Les couches, version 3 « théâtre de papier » (16/10/2026 ; tâche « Couches relief », 1 à 4 min par case)

Demande de David : les personnages coupés net, aucun contour qui bouge, aucune déformation autour d'eux. Chaque groupe de personnages est une carte plate (une seule profondeur, rien ne s'étire dedans), le décor est un plan (perspective d'ensemble, aucune bosse), et le décor caché derrière les personnages est reconstruit.

  1. Détourage (ComfyUI) : SAM 3.1 « person », un masque exact par personne ; puis, en un seul graphe, SAM cherche aussi les objets tenus (téléphone, écran, gobelet, verre, bouteille, papier, livre, bouquet, fleur, parapluie, appareil photo, micro, cigarette, sac, couteau), les objets portés (cravate, chapeau, écharpe, sangle), les surfaces qui montrent des gens (miroir, cadre photo) et les mains. BiRefNet ne sert plus qu'aux lisières oubliées par SAM et au bord doux (cheveux, flou).
  2. Qui va avec qui : un objet tenu suit la personne dont il touche une main (et pas un saladier qui touche un bras) ; un objet porté suit la personne qu'il touche ; les gens vus sur un écran, dans un miroir ou dans un cadre ne sont pas des sujets ; trous du masque bouchés ; fentes entre voisins comblées par la photo.
  3. Profondeur (ce PC) : Depth Pro d'Apple (gardée entre deux calculs), à défaut Depth Anything V2 Small. Sujets = personnes sur 0,4 % de la case au moins. Foule (plus de 45 % de la case) : le premier plan net (écart de profondeur), jusqu'à 35 % de la case, ou 60 % s'il est très net ou si tout le monde se détache du décor ; un morceau coupé par le bord du cadre (avant-bras, tête de dos) ne suffit jamais seul. Pas de premier plan net : pas de couches, la case glisse d'un bloc (carte plane, sans déformation).
  4. Deux cartes (devant / derrière) seulement si les deux groupes sont séparés par un écart de profondeur et ne se touchent pas ; sinon une seule carte (la partie cachée de la carte de derrière n'est pas reconstruite : elle s'ouvrait en croissant de décor).
  5. Décor caché : LaMa (prolonge les couleurs autour, n'invente rien) et Qwen-Image-Edit 2509 (invente un décor plausible dans une forme magenta ; contrôles SAM, photo recomposée, magenta restant ; 3 graines). Le réglage PLATE de app/layers.py choisit : qwen, lama ou hybride (LaMa près du contour, là où la parallaxe le montre, Qwen plus loin). Le décor reconstruit ne remplace la photo que sous les personnages, sur ~7 px autour et sur leur bord doux ; la carte est rentrée de 2 px (à 1 px, un liseré clair du fond partait avec elle).
  6. Lecteur : au repos, la photo exacte. Dès que la caméra bouge, le fond montre le décor reconstruit là où la carte s'écarte du fond de 2 pixels ou plus (écart local : le fond est un plan incliné). Avant le 16/10 au matin, un fondu jusqu'à 6 px d'écart moyen laissait voir, en transparence, le personnage lui-même décalé (« double nez », lunettes dédoublées) et ne finissait jamais sur les cases où les cartes bougent peu.
  7. Export : images/<case>_bg.jpg, _l1.webp, _l2.webp (RGBA), depth/<case>_ld.png (R = plan du fond, G et B = profondeur constante de chaque carte).

Fichiers bruts dans layers/<case>/raw/ (masques SAM des personnes, objets obj_*, worn_*, surf_*, hand, BiRefNet, profondeur, forme peinte, plaques plate.png = Qwen et lama.png) ; meta.json garde les essais (fill), les temps (timing) et la plaque utilisée (plate). Contrôle hors navigateur : les outils de test rendent les images exactement comme le lecteur (shader recopié en numpy).

Lancement : « Calculer » (cases en relief, sauf les vertes et celles déjà calculées) ou, dans l'aperçu en mode édition, onglet Relief : « Calculer les couches » / « Recalculer (autre essai) », « Utiliser les couches », vue « 🧩 Calques » (bleu = sujet du fond, orange = sujet de devant).

La carte (case sans couches)

  • Modèle : Depth Anything V2 Small, licence Apache 2.0 (distribuable, usage commercial permis), ONNX (onnx-community/depth-anything-v2-small), téléchargé une fois dans data/models/.
  • Entrée : l'image de départ de la case (start/), petit côté 518 px ; sortie normalisée (centiles 1–99), puis un plan ajusté sur cette profondeur (version 3, 16/10/2026) : la case glisse d'un bloc avec une légère perspective, sans aucune déformation (l'ancienne « nappe » s'étirait autour des personnages ; les cases vertes gardent leur carte validée).
  • Recalculée seule si l'image change ; bouton « Recalculer » dans l'aperçu ; plan net automatique = médiane du centre.
Depth Anything V2 Base / Large / Giant et Depth Anything 3 Large / Giant sont en CC-BY-NC : interdits.

Le mouvement

  • Respire : petite avancée puis retour (portraits, couples, détails).
  • Glisse : travelling latéral (groupes, paysages, tables).
  • Tourne : petit cercle autour du sujet (sujet central bien détaché).
  • Vertigo : le sujet garde sa taille, le fond s'éloigne (moments forts).
  • Au survol (boucle douce) ou au clic (un tour) ; la caméra suit aussi le glisser. Le plan net ne bouge pas : le mettre sur les visages (avec les couches, il est réglé d'office sur le sujet de devant). Cheveux, voiles, vitres : rester sous 3 %.
  • Lecteur : le fond et la nappe sont rendus par une recherche « premier point touché » (jamais de bord dédoublé, une pente trop forte s'étire) ; chaque sujet bouge d'un bloc, comme une carte de pop-up à peine bombée. L'avancée de caméra est bornée (Respire 0,3 ; Vertigo 0,35 au plus) : au-delà, l'image se déforme.
  • Biscuits : la formule conseillée met tout en relief et garde une vraie vidéo H3 par page (orbite 360 ou plan vivant en boucle) dans la grande case qui le mérite. Le réalisateur IA sait la choisir.
  • Relief d'attente : une case H3 dont le rendu n'est pas encore prêt s'affiche en relief.
  • Passer d'un traitement à l'autre (inspecteur, ou aperçu en mode édition) ne perd rien : les rendus H3 et les réglages du relief restent.

7 · Calculer

Les rendus H3 et la file

Où et comment

  • MiniMax H3 dans ComfyUI sur HITCHCOCK, CASSAVETES, FORD : nœud H3 Orbital pour le temps figé (orbite, chemins), MiniMaxH3ImageToVideo pour les plans animés ; LoRA 360 Orbit via LoraLoaderModelOnly ; la piste son native décodée (VAE audio H3) et gardée dans la vidéo.
  • fal : minimax/h3/image-to-video[/lora] (5–15 s, sans réécriture de prompt).
  • Boucle : la même image en première et dernière image (last_is_first).
  • Musiques : MiniMax Music 3 en local (passe après les vidéos de la machine).

Une file robuste

  • Un fil par machine, des fils fal ; les vidéos d'abord, puis les sons.
  • Reprise après redémarrage : les rendus en cours se rebranchent sur ComfyUI.
  • Erreur de mémoire passagère : une relance, ailleurs si possible ; machine muette : nouveaux essais pendant 15 min.
  • Indice de mouvement après chaque rendu : < 0,3 presque immobile ; 1,5 à 4,5 une case qui vit bien.
  • Une case en relief : sa nappe est calculée tout de suite, ses couches passent par la file (SAM 3.1, Qwen-Image-Edit).

9 · L'intelligence

L'IA et le réalisateur

  • Fournisseurs : Anthropic (défaut), OpenAI, Google, DeepSeek ; choix du modèle dans les réglages.
  • IA de case : regarde l'image et remplit caméra, action, sons ; réécriture de prompt pour « Régénérer » ; traduction des précisions.
  • Réalisateur IA (fenêtre 🎬) : une consigne globale ; une seule demande avec toutes les cases en images (ordre de lecture) ; il règle caméras, actions, textes, sons, voix, bruitages, musique de page, ambiance commune.
  • Traitement : vidéo H3 partout, relief partout + N biscuits H3 par page (avec la raison de chaque biscuit), ou au choix de l'IA case par case.
  • Compétences lues à chaque demande : app/skills/boucles.md (écrire des boucles parfaites : moteurs flux / relève / cycle / rythme, idle vivant, phrase de boucle, mots interdits, orbite 360 dans la plus grande case). On l'améliore en éditant le fichier, sans redémarrer.
  • Le réalisateur ne touche jamais aux cases vertes ni aux sons importés.

10 · Ce que voit le lecteur

Le lecteur

Cases vidéo

  • Vidéos tout-intra : le lecteur saute à l'image voulue (currentTime), au survol avec démarrage et arrêt doux, au glisser avec inertie, double-clic pour agrandir.
  • Boucle : points début / fin, fondu au raccord, ralentis joués plus vite (ease), aller-retour, vitesse.
  • Tremblé : fonction de la position dans la boucle, nombre entier de cycles : identique au raccord.
  • Couleurs et cadrage en CSS sur la vidéo.

Cases en relief

  • Un seul canevas WebGL par page (limite de contextes des navigateurs) ; chaque case dessinée dans son polygone.
  • Shader de point fixe (8 itérations) : uv = écran − (profondeur − plan net) × décalage ; sur-cadrage pendant le mouvement seulement.
  • Au repos, le dessin est identique à l'image de la page ; sans WebGL, l'image fixe.
  • Couleurs et cadrage dans le shader ; pas de tremblé.

Partout : sons au survol en fondu, musique de page qui baisse, bouton « Activer le son » (règle des navigateurs), noir et blanc, plein écran, livre (flèches, clavier, balayage, page suivante préchargée), tactile (la dernière case touchée joue).

11 · Retoucher sans recalculer

12 · S'y retrouver

L'accueil et les livres

  • Planches en vignettes (la feuille entière, à son format) ou en liste ; recherche ; tris : modification, création, alphabétique naturel, mieux notées, à retoucher d'abord.
  • Projets de rangement (distincts des livres, pas de publication) : barre « Toutes · Sans projet · un bouton par projet · + Nouveau projet » au-dessus des planches. Glisser une planche sur un projet la range (un seul projet par planche) ; ctrl / cmd + clic sélectionne plusieurs planches à glisser ensemble ; glisser sur « Sans projet » la sort. « ✎ Modifier ce projet » : nom, couleur, suppression (les planches restent). Une planche créée depuis un projet y est rangée. Stocké dans data/folders.json ; API GET / PUT /api/folders ({folders: [{id, name, color}], assign: {planche: projet}}).
  • Étoiles d'après les pastilles : vert 1, orange 0,4, rouge 0, moyenne ramenée de 1 à 5 par demi-étoile (toutes vertes = 5, jamais revue = 2,5).
  • Pastille de calcul : rouge qui clignote = rendu en cours, orange = en file (toutes les 4 s).
  • Plusieurs PC, un seul serveur : l'app tourne sur un seul PC (HITCHCOCK, 192.168.1.60, réglage server.host = "0.0.0.0" dans local_settings.json) ; les autres PC l'ouvrent dans leur navigateur à http://192.168.1.60:8790. Ne jamais lancer un 2e serveur sur les mêmes dossiers (verrou local seulement : risque d'écritures croisées). Port 8790 à ouvrir au pare-feu (réseau privé). Pas de mot de passe : réseau local seulement. Sauvegarde : tools/backup_nas.ps1, tâche planifiée « Alive-Comics sauvegarde NAS » chaque nuit à 3 h 30 vers \192.168.1.44 as\Backup\Alive-Comics-HITCHCOCK (copie sans miroir).
  • Onglets « Planches | Livres » en haut de l'accueil (l'onglet est retenu) : on passe de l'un à l'autre sans faire défiler.
  • Livres repliables ; ◀ ▶ pour l'ordre des pages ; clic sur une page : l'ouvrir, la voir, l'éditer seule ou dans le livre ; « Aperçu » et « Publier le livre ».

16 · Mémoire

Leçons apprises

H3 et les boucles

  • « slow », « tiny », « stays in place » donnent des vidéos figées (indice 0,05 à 0,3) : écrire un mouvement continu et visible.
  • Un geste qui « va quelque part » produit un aller-retour : moteurs flux, relève, cycle, rythme + idle vivant.
  • H3 freine au début et à la fin de chaque boucle (10 à 20 images) : c'est le « fixe » qui casse la boucle ; « Lisser la boucle » le corrige.
  • Pas de négation, pas de « loop / seamless » seuls, pas d'arc de 90° en boucle (la caméra revient).
  • Le filtre de contenu de fal refuse certains textes (« pieds nus… ») : message traduit pour David.

Le serveur et l'interface

  • Lire le corps de chaque requête dès l'arrivée (keep-alive) ; port exclusif sous Windows ; QuickEdit coupé.
  • Ouvrir l'onglet d'aperçu au clic (sinon bloqué), puis y charger la page.
  • Tremblé v1 trop fort (« faux 2D ») : v4 dans le lecteur, discret, raccord garanti.
  • Un raccourci « pastille seulement » a bloqué les remises à jour à corps vide : vérifier la présence de la clé.
  • Les identifiants de livres contiennent des tirets : les expressions régulières doivent les accepter.
  • Une interrogation ComfyUI sans réponse ne doit pas faire échouer un rendu (machine occupée).
  • Vérifier toute modification d'interface dans le navigateur ; scripts de correctifs en fichiers, pas en heredoc.

17 · Et maintenant

Limites et pistes

  • Réseaux sociaux : une planche ne joue pas dans le fil de X ou Instagram. À faire : un export vidéo de la page (MP4 carré, 9:16, 16:9, toutes les cases animées, avec le son) et des aperçus de lien (balises Open Graph, robots des réseaux autorisés tout en gardant Google dehors).
  • Relief niveau 3 : un calque par objet proche (banc, table) ; maillages en couches avec vraie caméra perspective (vertigo plus fort) ; profondeur MoGe-3 (MIT) + Marigold quand ComfyUI sera en 0.37+ ; double-clic agrandi pour les cases en relief.
  • Biscuits automatiques : bouton « Proposer les biscuits » sur la page, estimation de durée, biscuits en arrière-plan.
  • Musiques générées prioritaires quand une page attend seulement ses sons.
  • Republier d'un clic les livres en ligne après des retouches.
  • Mode automatique dans l'application (thème → livre), aujourd'hui assuré par l'instance de pilotage.
